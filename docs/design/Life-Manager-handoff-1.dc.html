Life Manager · design system v1

A ledger, not a
filing cabinet.

The point of view: this is a register of dates that happens to hold scans. So the system is built like a printed ledger — warm paper, an ink-black hierarchy, a serif for the things a human wrote (titles, dates, headlines) and a grotesk for the things the machine says (labels, status, controls). One accent-free palette: colour is spent only on status, never on decoration. There is no brand blue to admire, because the user opens this twice a month and wants an answer, not an identity.

Where I'd structure this differently from the brief: I collapsed "what needs doing" and "the horizon" into one screen. An all-clear screen that only says "all clear" is worthless twice a month. Instead the home screen always shows the forward timeline — the next expiry however far away — so the answer is never nothing, it's "nothing until 4 March." That single change fixes the hardest state in your list.

1 · Colour

Light and dark at full parity, same token names, because a PWA opened at 11pm in bed is a real case. Light mode is paper (#F7F5F0), not white — white plus a serif reads like a document viewer, and this isn't one. Dark mode is warm near-black, never pure #000, so the hairlines survive. Three status hues only, each pulling double duty as a background tint. Nothing else is coloured — no coloured type per document type, because seven type-colours is a code the user won't learn in a session-every-two-weeks.

2 · The expiry ladder — five states, readable in greyscale

Each state changes four things at once: the glyph's shape, the words, the type's weight, and its case. Colour is the fourth wheel, not the axle. The gauge is a fuel gauge for time — three bars, filling as the deadline recedes. Zero bars is never shown: at zero the shape changes instead, which is the point.

4 · Navigation — three tabs, and how it absorbs five more domains

Three tabs, permanently visible, always labelled: Now · Documents · Add. No gestures to learn, nothing behind a hamburger, and Add is a tab rather than a floating button so it can't be mistaken for decoration.

The scaling move: domains never become tabs. When assets, money, people and the vault arrive, the middle tab's title becomes a domain switcher — one tap on "Documents ⌄" swaps the collection under the same search, the same filters, the same row. Now stays a single cross-domain deadline feed; a car's MOT and a passport's expiry belong in the same list, and that's the cross-domain payoff you described. Add becomes a two-row sheet: "what are you adding?" then the same one-required-field form. Tab count stays three at six domains.

Why not five tabs: at two-week intervals the user relearns the bar every time. Three labelled tabs is one glance.
